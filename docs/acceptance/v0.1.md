## D: 実際の機能追加

公開CLIで新規アプリを生成し、生成物のAGENTS.md、README、docsの追加手順・構成・規約・Domain境界・連携・DB・認可・監査を読んだ。Equipmentの入力・service・repository・Server Action・UIを具体例として使用した。採用版Next.js同梱文書でServer Actions / headers / redirect / notFound / revalidatePathを確認した。

依頼は「社員ごとに研修名・受講日・有効期限・修了状況・備考を管理する」。業務上の補足は生成物のdocs/training.mdに記録した。Admin / Managerが管理、Userは組織内の閲覧のみ。期限は任意で受講日以降、同じ研修の再受講を許可する。無効社員の履歴は保持し、既存受講者のまま編集できる。

[再現可能な差分](../../examples/training-acceptance/README.md)を保存した。標準テンプレート・公開済みCLIのアプリ内容は変更していない。新しい依存も追加していない。

検証した内容:

- 不正日付・期限・状態・UUID・長さ、ロール表、監査snapshotの秘匿属性除外。
- 実DBでCRUDと監査、越境した読出し／更新／受講者参照の拒否、複合外部キー、降格・無効操作者、無効社員の履歴編集。
- 監査INSERT失敗時の登録・変更・削除の取消。
- 既存6 Migration → Seed・備品・監査データ → Training Migrationの追加 → 再適用。既存User・Department・Equipment・Auditのデータ保持。
- 1280 / 768 / 390pxで登録・修了へ更新・文字列としての備考表示・Manager削除・削除後404・User閲覧と更新非表示・登録URL拒否・降格後の古いフォーム拒否。既存の認証・User / Department・Equipmentも回帰検証。

本体の`npm run check`も成功した。保存した差分を新しいnpmキャッシュ・別の一時生成アプリへ適用し、`npm run test:acceptance:db`でcheck・Migration / Seedの再実行・実DB32件・3画面幅の業務操作まで再現できた。

大量データのページング、期限通知、受講時点の部署履歴、本人だけの閲覧、添付ファイル、外部APIは今回の追加要件に含めていない。

## F: 設計レビュー

TrainingはorganizationIdと既存UserへのuserIdを持つ。所属部署はそのUserの現在のDepartmentから読む。Employee / Teamの重複モデルはない。研修名・日付・期限・修了状況・備考をUserやDepartmentへ追加せず、Trainingに保持する。

src/trainingのservice / repositoryはEquipmentをimportせず、備品テーブルも参照しない。追加はCoreのrelation・Permission・安全な監査projection・メニューと、独立したTraining Featureに限る。監査モジュールにTraining serviceをimportしない。UIとHTTPに依存しないsaveTraining / deleteTrainingを将来のAPI入口から利用できる。現在APIがあるとは扱わない。

共有Userの所属変更がTrainingの部署表示へ反映され、備品データが保持されることを実DBで検証した。既存機能の全テストも成功した。Domain境界・共有マスタ再利用・追加時の既存データ保全を満たす。

## G: 連携シナリオ

人事がUser / Department、総務がEquipment、教育がTrainingを管理する。同一社員はUser.idで参照し、同一組織の境界をorganizationIdで強制する。人事が所属を更新すれば教育の画面も同じ部署を表示する。教育用Employeeを別途同期する必要はない。

現在は単一Next.jsアプリとPostgreSQLで十分。部門ごとのPermission割当や本人限定スコープ、外部システム同期は別途要件を定義する。マイクロサービスやイベント基盤を先行追加していない。

## Eの後日確認と正式版への条件

ユーザーがClaude Code確認を後日に指定したため、Milestone 15とA〜G全体は完了扱いにしない。別AIが生成アプリのAGENTS.md / CLAUDE.mdとdocsを読み、モデルの所有・共有マスタ・Permission・監査transaction・API入口・テスト手順を正しく説明できるか、独立して確認して記録する。

同じアプリは公開RCと保存した差分から再生成できる。[Claude Codeへのレビュー依頼](../../examples/training-acceptance/claude-review.md)を用意した。Claude Codeの説明・対象版・実行環境・不足点を記録し、不足があれば生成文書やテンプレートを修正して関連検証を行う。

正式版は全体の受入判定後に0.1.0として配布内容を固定し、検証・公開・Registry再検証を行う。latestは正式版、nextは候補版の入口とする。現時点ではnext / latestともに0.1.0-rc.0のまま。タグの意図だけを理由に候補版を正式版として案内しない。
