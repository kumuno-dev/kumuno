# 医療機器管理テンプレート設計案

作成日: 2026-10-01。ユーザーのExcelによる医療機器管理と、指定された参考サイトをもとにした提案。第一段階の台帳をソース版へ実装した。後続は提案であり、v0.1の既存完了条件や公開済みCLIの機能を変更するものではない。

## 参考サイトで確認したこと

[参考サイト](https://v0-sowa-one.vercel.app/)をブラウザーで読み取り確認した。登録フォームは開いて項目を確認し、保存・返却・修理などの更新は行っていない。サーバーへの永続保存や権限チェックは未検証。

| 画面 | 確認した構成 | KUMUNOへの取り込み案 |
| --- | --- | --- |
| ダッシュボード | 機器数、貸出・点検状況、種別別の待機数、通知 | 同じ機器台帳と履歴から集計し、一覧へ移動できる入口 |
| 機器管理 | 検索、種別・状態の絞り込み、台帳、登録フォーム | Excelから移行しやすい台帳と機器詳細 |
| 貸出・返却 | 利用可能機器と貸出先の選択、貸出中・返却済み一覧 | 病棟・部屋単位の貸出と返却履歴 |
| 点検業務 | 機器、日付、担当者、点検種別、項目、結果、次回予定 | 機器ごとの履歴と次回予定の一覧 |
| 点検表テンプレート | カテゴリ・点検種別・項目数 | 後続工程で施設の項目を設定できる機能 |
| 修理管理 | 不具合、報告者、優先度、対応状態、担当 | 後続工程で修理中の貸出制限と履歴 |
| タブレット | 大きな貸出・返却ボタン、台数表示 | 台帳完成後、現場操作専用の入口 |

余白のある一覧、左側ナビゲーション、色と文字を併用した状態表示、大きな操作ボタンを参考にする。KUMUNOのオレンジをアクセントに使う。既存サイトのコード・画像・ロゴをコピーせず、KUMUNOの構成で実装する。

参照画面には機器番号・日付・点検表名の不整合が見られたため、サンプル値を要件として採用しない。日付は統一書式、集計と一覧は同じデータを使う。

## 最初の範囲と広げ方

1. **台帳**: 機器の登録・編集・検索・詳細。架空のサンプル機器と「まず1台登録する」案内で入口を作る。
2. **貸出・返却**: 病棟等への貸出、返却、履歴。台帳から現在の場所と次の操作が分かるようにする。
3. **点検**: 点検記録、次回予定、返却後の点検と貸出可能への復帰。実際の施設の運用を確認して状態遷移を確定する。
4. **展開**: 修理、点検表テンプレート、Excel/CSV取込、タブレット、QR等を必要に応じて追加する。

初回は台帳を完成させ、各段階で保存・再起動後の保持・権限・履歴まで確認する。全メニューを空画面として先に並べない。CLIのテンプレート選択方式は、この業務の小さな実装を確認してから決める。

## 台帳の項目案

参考サイトの登録フォームにある機器管理番号、資産管理番号、種別、機器名、メーカー、型式、シリアル番号、設置場所、購入日、保証期限、状態、備考を出発点にする。

- 内部UUIDは表示番号と分離する。機器管理番号は組織内で一意とする案。資産番号の必須性・重複可否は実際のExcel運用で確定する。
- 種別は施設で増やせる構成を検討する。最初の例は人工呼吸器・輸液ポンプ等の架空機器。
- 所有部署と現在の設置場所を区別する。設置場所は既存Departmentを参照する場所マスタで扱う案。
- 参考サイトには患者名入力がある。患者との関連付けは別途要件を確認するまで実装範囲に含めない。患者名を機器台帳の自由入力属性として安易に追加しない。

## KUMUNOの基盤との接続

業務機能は `src/medical-equipment/` を候補とし、既存のOrganization・Department・User、認証・認可・監査を利用する。独自の病院・職員マスタを重複作成しない。現行Equipmentの一般備品向け状態をそのまま医療機器の貸出状態として転用しない。新しい業務モデルか既存台帳の拡張かは実装開始時に比較し、同じ機器を二重管理しない方式を決定する。

貸出・点検・修理は業務固有の履歴を所有し、担当者は既存Userへ関連付ける。更新と監査は同じトランザクションで保存する。すべての操作で組織境界と最新の権限を確認する。

状態の候補は待機・貸出中・点検待ち/点検中・修理中・廃棄。貸出や修理の履歴と矛盾する状態を自由編集させない。返却直後に待機へ戻すか点検待ちにするか、同時貸出の禁止、点検不合格後の操作を実装前に確定する。点検項目・判定基準は施設の手順に基づいて設定し、参考サイトの例を臨床上の標準として扱わない。

## 各段階の確認

- 台帳: 登録・編集・検索、番号重複の拒否、他組織の参照/更新拒否、読取専用ユーザーの更新拒否、保存と監査の同時成立、再起動後の保持。
- 貸出: 同じ機器への同時貸出を防ぐ。返却済み履歴を保持し、現在地・台数と一覧が一致する。
- 点検: 記録と次回予定を保持し、確定した業務ルールに従って貸出可能性が変わる。
- UI: PCとタブレットで、現在の状態と次の操作を文字でも判断できる。

既存Excelの列、病棟貸出と患者への割当の関係、返却後の点検手順は未確認。これらを確認しながら段階的に具体化する。

## 第一段階の実装判断

MedicalDeviceを独立した業務モデルとして追加した。一般備品Equipmentの状態を医療の貸出可否へ転用しない。同じ機器の二重登録は行わず、共通マスタのみ再利用する。資産番号は任意・重複可、所属部署は既存Department、設置場所と種別は文字入力とした。場所マスタと貸出時の状態遷移は後続で具体化する。

台帳の状態は運用中・運用停止・廃棄済みで、貸出可否を表さない。サンプル機器の自動登録は行わず、初回案内から1台登録できる。現在は既定生成物に追加した業務例であり、医療テンプレート選択のCLIオプションはまだ提供していない。[生成物の仕様](../../templates/default/docs/medical-equipment.md)を参照。

## 第二段階の実装

病棟等への貸出・確認付き返却・検索可能な履歴・現在の貸出先表示を追加した。返却後は点検待ちで再貸出を止める。点検と解除処理は次工程。[判断0024](../decisions/0024-medical-device-loans.md)を参照。

## 第三段階の実装

点検内容・結果・担当者・次回予定の履歴、結果による再貸出の可否、合格後の点検待ち解除を追加した。点検表テンプレートと修理は別工程。[判断0025](../decisions/0025-medical-device-inspections.md)を参照。

## 第四段階の実装

修理依頼・対応開始・完了と履歴検索を追加した。修理中は運用再開・貸出・点検を拒否し、完了後も台帳での運用再開と合格点検を必要とする。[判断0026](../decisions/0026-medical-device-repairs.md)を参照。

## 任意の試用データと運用概要

テストデータあり/なしを選べる架空7台を追加した。次工程として医療ダッシュボードの台数集計・状態別台帳への導線・点検予定を実装した。点検表テンプレート・Excel取込・タブレット専用画面は後続。
