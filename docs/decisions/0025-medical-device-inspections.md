# 0025: 点検記録と合格後の再貸出

2026-10-01。ユーザーが点検記録と点検完了後の再貸出の実装を依頼した。

MedicalInspectionは医療機器Domainの履歴を所有し、Organization・MedicalDevice・Userと、関連する返却MedicalLoanを参照する。独立した点検者マスタを追加しない。結果は合格・不合格・未完了、内容は施設の手順に沿った入力とする。臨床的な判定基準や点検表の固定項目を推測して同梱しない。

点検待ちの解除は合格かつ運用中の場合のみ。不合格・未完了は再貸出を止める。運用停止を点検から自動解除しない。貸出中と廃棄済みの点検を拒否する。既存点検の編集・削除は提供せず、追記で履歴を保持する。

機器のupdatedAtによる版確認とPrismaの行ロック、Serializableトランザクションを組み合わせる。古い点検フォーム、同じフォームの二重保存、貸出や返却との競合を拒否する。返却後の合格の日付は直近返却日以降とし、関連する返却履歴を保存する。過去の合格で新しい返却後の点検待ちを解除しない。

点検・機器の状態変更・両監査を同じトランザクションで確定する。点検内容の自由入力は監査から除外する。操作担当者と記録日時はサーバーで設定する。

[実装仕様](../../templates/default/docs/medical-equipment.md)を参照。現在試用中のローカルデモは、停止・バックアップ後にコードと追加Migrationを適用し、既存データと資格情報を保持して再起動する。

点検日判定から既存の返却時刻取得に9時間の時差が重複する不具合を発見した。一括データ補正は自動承認レビューに拒否されたため実施しない。既存履歴と監査を保持する読取時の互換処理を採用し、元の返却監査のDB時計を表示/判定に利用する。新規返却はタイムゾーン付きDB文字列をDateへ変換して保存する。旧時刻データを保持した追加Migrationと互換表示をテストする。

検証: 単体28件・実DB46件・スモーク4件・本番ビルド・3画面幅の不合格→合格→再貸出、再起動後の保持が成功。最終的な返却選択と点検の版の変更は関連実DB3件でも確認した。実際の試用デモは停止後に私有バックアップを作成し、既存台帳・貸出・監査の件数とハッシュを保持して更新・再起動できた。
