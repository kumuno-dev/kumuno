# 0013: 業務更新と同一トランザクションの監査ログ

日付: 2026-09-29

Milestone 7の必須項目と変更前後をAuditLogへ保存する。組織境界と将来の調査に備えorganizationIdを必須にし、対象と日時の索引を付ける。ログは追記専用。UPDATE / DELETE / TRUNCATEをDBトリガーで拒否する。DB管理者の改変まで防ぐ暗号学的な証跡や外部保管は今回の対象外。

既存の部署移動とユーザー無効化を監査対象にする。成功した業務更新だけを記録し、ログ保存に失敗した場合は業務更新・セッション削除もロールバックする。両サービスのactorIdを必須にし、トランザクション内で最新ユーザーの権限・組織を確認する。既存の内部呼出テストも新しい引数に合わせる。

変更前後はリソース別の許可リストから生成し、資格情報・個人の連絡先を含めない。metadataは固定のversionのみ。対象リソースと操作者の削除後も履歴を残すため、それらには外部キーを付けない。OrganizationだけはRestrictで参照する。新規依存はない。監査閲覧画面やログイン履歴は今回実装しない。
