# 0036: アプリ内通知を共通化する

日付: 2026-10-05。承認済みのパッケージ化順序の第7段階。

@kumuno/notificationsは有効な操作者と同じ組織の有効な受信者、文字列の通知属性、dashboard内の相対リンクを検証し、渡されたwriterを呼ぶ。Prisma・Next.jsには依存しない。組織、受信者、イベントキー、タイトル、本文、リンクのみ投影する。writerの失敗を呼出し元へ伝える。

生成アプリはセッションと最新操作者、Notificationモデル、受信者ごとの一覧・既読状態、監査とtransactionを所有する。最初の接続は医療機器CSVの一括登録完了。登録者本人へ取込単位で1件を送り、機器・監査・通知を同じSerializable transactionで保存する。本文とリンクの組立ては医療Domainに置く。

一覧・未読件数・既読更新は組織と受信者本人に限定する。dashboard:readで参照でき、管理者でも他者の通知を操作できない。既読更新は未読状態を条件に更新し、最初の時刻と1件だけの監査を維持する。通知本文はHTMLとして解釈しない。

追加Migrationで既存データを維持する。通知の複合外部キーは別組織の受信者を拒否し、受信者の物理削除では通知だけを削除する。監査は履歴IDを保持し、通知本文を記録しない。過去の取込への通知生成は行わない。

未公開tgzをCLI候補rc.2へ同梱する。メール・プッシュ・配信キュー・定期通知・一括配信・承認業務の通知は後続。npm公開は別工程。

検証: パッケージの属性・リンク・権限・失敗伝播、独立導入と公開型、実DBの受信者境界・ページング・既読監査・全体ロールバック、配布CLIの3画面幅の登録→通知→既読を確認する。
