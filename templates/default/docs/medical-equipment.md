# 医療機器台帳

医療機器管理の第一段階として、機器の登録・編集・詳細・検索・状態の絞り込み・ページ切替を提供する。ログイン後の「医療機器台帳」から使う。まず機器管理番号・機器名・種別を入力して1台登録する。

## 項目と運用

機器管理番号（必須、組織内一意）、資産管理番号（任意、重複可）、機器名・種別（必須）、メーカー、型式、シリアル番号、所属部署、設置場所、購入日、保証期限、備考を記録する。表示番号は内部UUIDと分離する。種別と設置場所は現段階では文字入力。部署は既存Departmentを使う。

台帳上の状態は運用中・運用停止・廃棄済み。これは貸出可能性や点検合格を表さない。削除せず廃棄済みへ変更して記録を残す。貸出・返却と履歴を実装済み。点検記録と合格後の再貸出を実装済み。修理依頼・対応開始・修理完了と履歴も実装済み。患者との関連付け・Excel取込・テンプレート選択は後続工程であり未実装。

備品とは別のMedicalDeviceモデルで医療固有の属性を管理する。同じ医療機器を備品にも二重登録しない。一般備品からの自動移行は行わない。

## 権限と監査

ADMINとMANAGERは参照・登録・編集、USERは参照のみ。serviceはトランザクション内で最新のユーザー状態・組織・権限を確認する。他組織の機器と部署を拒否する。Organization・Department・Userを重複作成しない。

登録・編集とMedicalDevice監査を同じSerializableトランザクションで保存する。監査は許可した台帳項目のみを投影し、備考を含めない。自由入力欄へ患者情報を記録する用途は想定していない。

## 配置とDB更新

`src/medical-equipment/`に入力検証・repository・service・Server Action・フォームを置く。画面は`src/app/dashboard/medical-equipment/`。Prisma Migration `20261001090000_medical_device`は新しいテーブル・列挙型・制約を追加し、既存テーブルを変更しない。

新しく生成したアプリは通常のdb:migrate、またはdev:localで適用される。古い生成アプリは自動更新されない。既存アプリへのコード移植は、そのアプリの変更を確認し、バックアップとMigrationの検証を行ってから実施する。

## 検証

入力検証、実DBでの保存・編集・重複拒否・組織境界・最新権限・監査失敗時の取消・検索/ページ、既存6Migrationからのデータ保持、PC/タブレット/スマートフォンでの操作をテストする。dev:localの検証には停止・再起動後の台帳と監査の保持を含む。

## 貸出・返却

機器詳細の「貸出・返却」で貸出先の部署（必須）と場所（任意）を入力し、「貸出を登録」を実行する。台帳と詳細に現在の貸出先を表示する。「医療機器の貸出・返却」メニューから貸出中/返却済み一覧を検索し、ページを切り替えられる。

返却は実際の機器の返却を確認したチェックが必要。貸出日時・返却日時はサーバーで記録し、画面は日本時間で表示する。貸出・返却担当者はログインした既存User。貸出先名は当時の部署名を保存し、部署を改名しても履歴が変わらない。台帳の所有部署・設置場所は書き換えず、現在の貸出先を別に表示する。

貸出中の機器は二重貸出、運用停止・廃棄への変更を拒否する。停止・廃棄済みの機器も貸出を拒否する。返却後はreturnInspectionPendingをtrueにし、点検待ちとして再貸出を止める。台帳編集で運用中にしても点検待ちは解除しない。点検記録で合格した運用中の機器だけ点検待ちを解除する。新規機器の運用中という状態も、臨床上の使用適合性を保証するものではない。

MedicalLoanは同じ組織のMedicalDevice・Department・Userへ複合外部キーで関連付ける。同一機器の未返却履歴は部分一意インデックスで1件に制限する。機器行をロックし、Serializableトランザクションで業務ルールと最新権限を確認する。競合時は再読み込みを案内する。

貸出はMedicalLoanのCREATE監査、返却はMedicalLoanと点検待ちに変えたMedicalDeviceのUPDATE監査を同じトランザクションに保存する。場所等の自由入力は貸出監査へ投影しない。履歴は編集・削除する操作を提供しない。関連履歴のある部署・機器・操作担当者の削除は外部キーで制限される。

Migration `20261001100000_medical_loans`は既存7Migrationにテーブル・台帳の点検待ちフラグ・制約を追加する。既存機器の点検待ちはfalseとして保持する。

## 点検記録と再貸出

機器詳細の「点検記録」→「点検を記録」から、点検日・種類（返却後/定期/その他）・結果（合格/不合格/未完了）・実施内容・任意の次回予定を記録する。担当者はログインしたUser、記録日時はサーバーで付与する。施設の手順に沿った内容を入力し、確認にチェックして保存する。既定結果は未完了。固定の臨床的チェック項目や合否基準は同梱しない。

合格した運用中の機器は点検待ちを解除して再貸出できる。不合格・未完了は点検待ちにする。運用停止の機器へ合格を記録しても、停止状態を変えず再貸出を許可しない。必要な運用停止解除を台帳で行った後、改めて点検を記録する。貸出中・廃棄済みの機器には点検を登録できない。

機器のupdatedAtをフォームの版として確認する。状態が変わった古い点検フォームを拒否し、過去の合格記録を新たな返却の解除に再利用しない。返却後の合格点検の日付は直近の返却日（日本時間）以降。返却後点検には返却履歴が必要。関連する返却履歴のIDも保存する。点検日を未来に設定したり、次回予定を点検日より前に設定する入力は拒否する。

MedicalInspectionの追加、MedicalDeviceの点検待ち変更、両方の監査を同じSerializableトランザクションで保存する。点検内容の自由入力は監査へ投影しない。履歴は追記のみのサービスとし、編集・削除するUIは提供しない。訂正時は新しい記録を追加する。同じフォームの二重送信・同時送信は1件だけ確定する。

メニューの「医療機器の点検記録」から検索・結果の絞り込み・ページ切替ができる。機器詳細には最新10件と次回点検予定を表示する。点検表テンプレート・通知・修理対応は別工程。

配置はsrc/medical-equipment/inspections.ts / inspection-action.ts / inspection-panel.tsx、一覧はsrc/app/dashboard/medical-inspections。Migration `20261001110000_medical_inspections`は点検テーブル・列挙型・組織境界の外部キーを追加する。既存8Migrationの機器・貸出・返却・点検待ちは保持する。

### 旧返却時刻との互換性

以前のraw timestamptz取得に時差が重複する不具合があったため、新規返却はタイムゾーンを含むDB文字列から時刻を取得する。既存の該当履歴は書き換えず、元の返却監査（変更前は未返却、変更後の返却時刻と操作担当者が一致）のDB記録時刻を表示と点検日判定に利用する。一致する監査がない記録を推測補正しない。直近の返却は、同時貸出禁止の下で貸出順から選ぶ。

## 修理管理

「医療機器の修理記録」で機器名・管理番号と状態を検索できる。機器詳細の「修理管理」から不具合を入力し、確認チェック付きで修理を依頼する。貸出中・廃棄済みの依頼は拒否する。依頼時に運用停止・点検待ちへ変更し、修理中の貸出・点検・運用再開・廃棄を拒否する。

修理依頼 → 対応中 → 修理完了の順で操作する。完了時には修理対応の内容を必須とする。依頼者は既存User、操作担当者は監査に残り、日時はサーバーで記録する。完了しても運用停止・点検待ちは自動解除しない。施設の手順で運用再開を確認し、台帳を「運用中」に変更した後、改めて修理完了日以降の合格点検を記録する。その時点で再貸出できる。

MedicalRepairは同じ組織のMedicalDevice・Userへ複合外部キーで関連付ける。未完了の修理は機器ごとに1件。行ロック・Serializableトランザクション・部分一意制約で重複と競合を防ぎ、最新の権限を確認する。依頼と機器の停止、各状態遷移と監査を同時保存する。不具合・修理内容は業務記録に保存し、監査へ自由入力を投影しない。完了した履歴の編集・削除は提供しない。

Migration `20261001120000_medical_repairs`は追加DDLのみで既存データを変更しない。修理業者・費用・添付・点検表テンプレートは未実装。
