# アプリ内通知

ログイン後の「通知（未読○件）」から自分の通知を確認する。「すべて」「未読のみ」を選び、1ページ20件で表示する。「既読にする」で未読件数が減り、「関連画面を開く」で業務画面へ移動する。

現在は医療機器CSVの一括登録完了時、登録者本人へ取込単位で1件だけ通知する。登録台数と点検待ちの案内を表示し、点検待ち台帳へリンクする。過去の取込について通知を追加しない。

## 保存・権限

Notificationは組織、受信者、イベントキー、タイトル、本文、相対リンク、作成日時、既読日時を持つ。組織・受信者・キーで重複を拒否し、受信者と組織の複合外部キーで越境を防ぐ。受信者の物理削除時は通知を削除するが、監査履歴は保持する。

セッション由来の組織・本人で参照と更新を絞る。dashboard:readが必要で、管理者にも他者の通知は見せない。既読の再更新は時刻を変えず、監査を追加しない。更新transactionで最新の有効状態を再確認する。

機器の登録・各機器の監査・通知・通知の監査は同じtransactionで保存する。いずれかの保存が失敗すれば全件を取り消す。既読更新と監査も同時に保存する。Notificationの監査属性は受信者IDと既読時刻のみで、本文・タイトル・CSV内容は記録しない。

## 共通パッケージと境界

@kumuno/notificationsは有効状態・同じ組織・属性の長さ・dashboard内の相対リンクを検証してwriterを呼ぶ。タイトル160文字、本文1000文字、キー200文字、リンク2048文字まで。本文はプレーンテキストとして表示する。DB・認証・受信者決定・業務文面・既読UIはアプリ側に置く。

src/notificationsは保存・一覧・既読操作、src/medical-equipmentは取込完了の文面と呼出しを所有する。vendorの未公開tgzを同梱しているので、生成アプリは親リポジトリなしで導入できる。モデル変更後はMigrationとPrisma Client生成が必要。

メール・プッシュ・定期送信・一括配信・全件既読・通知削除UI・承認通知は未実装。検証はtest:dbとtest:authで行う。実運用DBへのテスト登録は行わない。
